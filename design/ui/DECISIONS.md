# Decisions

Log of product and design decisions for the Gazebo Bevy UI. Newest at the bottom. Each entry: what was decided, the alternatives, why, and where the spec reflects it. Implementors append here when they make a call the spec left open.

## 2026-10-18 · Frame and direction (summary of the design sessions)

- **D-01 Layout: activity-sidebar workbench.** Alternatives: fixed workbench with tool rail (W1), ribbon + timeline (W3), viewport-first floating UI (Direction B). Chosen for density, keyboard reach and a stable frame. Spec §2.
- **D-02 Theme: light first, dark second, both tokenized.** Spec §4, tokens.json.
- **D-03 Shortcuts follow Gazebo (Esc, T, R).** Unity-style Q/W/E rejected because the users come from Gazebo. shortcuts.json.
- **D-04 Default tool is Navigate:** click selects, left-drag orbits, right-drag pans, wheel/middle zooms. Box select is its own tool (B). Spec §6.1.
- **D-05 Camera controls live on the viewport only**, as one cube + one rail; nothing that edits the world is on the viewport. Spec §3.4.
- **D-06 File actions live in the world-name menu**, not the top bar. Spec §7.1.
- **D-07 Workspaces switch from the status bar.** Spec §7.8.

## 2026-10-18 · Review follow-ups (Q1–Q7)

- **Q1 Second panel → second stacked slot in the sidebar.** Alternative: pop-out only. Chosen because Topics→Plot, Sensors↔Teleop and the Debug workspace need two docked panels, and pop-outs cover the scene. Pop-out stays as the escape hatch. Spec §3.3.2, §7.11.
- **Q2 Workspaces button removed from the activity bar.** Alternative: keep both entry points. One place per job; the status-bar switcher gains "Manage workspaces…". Spec §3.2, §7.8.
- **Q3 Delete moves behind the inspector's more-actions menu.** Alternative: keep as a quick action with an Undo chip. Chosen for safety; Delete key, context menu and ⌘Z still make it fast. Quick actions become Focus / Duplicate / Save as… (Model) and Focus / Duplicate / Hide (Light). Spec §3.5.
- **Q4 Space tap = play/pause.** Alternatives: ⌘⏎ chord, no key. Chosen because it is the convention in sim and video tools. Tap is < 200 ms with no drag; hold+drag stays temporary Pan. Space never fires in text fields. Risk accepted: a stray Space starts the sim; mitigated by the Undo-free nature of pause and the visible Play button state. shortcuts.json `sim.play_pause`.
- **Q5 X = Teleop emergency stop**, only while Teleop is armed; gizmo drags are disabled while armed so X never means "constrain X" at the same time. shortcuts.json `teleop.stop`.
- **Q6 Model editing happens in place.** Alternative: separate full-screen editor. Chosen to keep world context and avoid a second frame. Sim pauses, other entities dim, EDITING pill with Done, Assets gets a Parts tab. Spec §6.6.
- **Q7 Backends: native speaks gz-transport directly from Rust; web speaks websockets.** Alternative: a bridge process for both. Chosen so the desktop build has no sidecar and the web build uses the standard Gazebo websocket server. Spec §9.4.

## 2026-10-19 · gzweb-rs implementation decisions

- **D-08 Desktop connection deferred (amends Q7).** Both desktop and web use the Gazebo websocket server for now, behind a `SimBackend` trait. A Rust gz-transport client is a later, separate track. Why: gzweb-rs already speaks the websocket protocol on both targets, and every panel can be built on it. See `.agent/UI_PLAN.md` §3.
- **D-09 First target release: Gazebo Jetty (gz-sim 10)** (answers open Q2). In Jetty the websocket server is the gz-sim system `gz-sim-websocket-server-system` (gz-launch is deprecated). See `.agent/UI_PLAN.md` §3a.
- **D-10 UI modes.** gzweb-rs runs in three modes: `none` (snapshot/screenshot), `minimal` (3D view, orbit camera, viewport keyboard bindings, no panels) and `full` (this spec). Defaults: `full` on desktop, `minimal` on the web. Alternative considered: one mode with collapsible chrome. Rejected because embeds and kiosks need a bare view with no UI cost. See `.agent/UI_PLAN.md` §2.

## 2026-10-19 · M0: views and the minimal mode

- **D-11 Plain wheel zooms about the view centre; Ctrl+wheel and pinch zoom to the cursor.** Alternative: keep gzweb's wheel, which already zooms to the point under the cursor, making Ctrl+wheel redundant. Chosen so the two §6.2 rows differ. Middle drag zooms about the point under the cursor at drag start (the drag pivot rule). With nothing under the point (sky), the zoom centre is the point on its ray at the old pivot depth, never the origin. Pinch: in Chrome and Firefox a trackpad pinch arrives as a wheel event with `ctrlKey` set but no Control key-down, which Bevy's input doesn't show (bevy_winit 0.20 reports no Control key and unknown modifiers), so a `passive: false` wheel listener on the canvas cancels the browser's page zoom and flags the frame, and a flagged wheel without Control held zooms to the cursor by the pinch's scale (`deltaY ≈ -100·ln(scale)`); Safari's `gesturechange` does the same; native macOS has `PinchGesture`. A wheel notch is one step everywhere: native lines are steps, browser pixels 100 per step (Chrome's notch), browser lines 3 per step (Firefox's notch); a frame's wheel input is summed and capped at 5 steps. Spec §6.2.
- **D-12 Minimal-mode fly keys live in a small `minimal`-scope table next to shortcuts.json.** W/S move along the view direction flattened onto the ground (looking straight down: up the screen), A/D sideways, Q/E world down/up; speed is half the distance to what the view centre sees per second (D-20), frame-rate independent, at most 0.1 s a frame; in orthographic views they move in the screen plane (D-20); Ctrl/Alt/⌘ held disables them. Alternatives: add them to shortcuts.json (the file has no minimal mode), or move in the screen plane. Scope `minimal` never overlaps `teleop`, so the conflict test covers both without a clash. `.agent/UI_PLAN.md` §2.3.
- **D-13 Axis views follow the Gazebo GUI** (gz-sim `ViewAngle` with gz-math `LookAt`): front looks along −X, right along −Y, back and left opposite; top looks down with +X up the screen, bottom up with −X up. They snap about the selection centre, else the point at the view centre, else the current pivot, keeping the distance. Alternative: Blender's numpad convention (front looks along +Y). Chosen for D-03 (follow Gazebo). Spec §3.4, §6.3.
- **D-14 Focus (F) frames, in order: the selection; the top-level model under the cursor, without its plane visuals (over a ground model, which has nothing else, it falls through); the world without plane visuals (a 100 m ground plane would swamp it); home.** Spec: "F frames selection; no selection: frames the world"; the cursor step gives minimal mode, which has no selection, a way to frame one model. Spec §3.4 rail, shortcuts.json `view.focus`.
- **D-15 How the shortcut conflict rule (§13) reads the file.** Every scope pair overlaps except `minimal`/`teleop`. Pairs the spec declares mutually exclusive are listed in code (`tool.constrain_x`/`teleop.stop`, Q5). A tap and a hold on one chord (Space) don't conflict (Q4). In the browser `mod` is either Ctrl or ⌘, because a page can't tell which the platform means. Keys are physical key positions (US names) and digits also match the keypad; layout-aware letters wait for M10.
- **D-16 Minimal mode binds no reset, and step only steps a paused sim.** ⌘⇧R was to need the Undo chip (§7.1) that only the full UI has; Reset isn't undoable now (D-89), and minimal mode still binds none, so a stray chord can't reset a world. ⌘→ while running does nothing, as N did. gzweb-rs's old N (step) key is gone; ⌘→ replaces it. Space tap needs the world stats to know whether to play or pause; before they arrive it does nothing.
- **D-17 Step keeps ⌘→ / Ctrl+→ in the browser; the canvas swallows it.** The spec lists `sim.step` (`mod+Right`) neither in `web_reserved` nor in `prevent_default_when_canvas_focused`, but ⌘→ is Forward in Chrome (and ⌘← Back) on macOS, so a step would navigate away. Browsers deliver these chords to the page, so no `web_alt` is needed: `mod+Right` joins `prevent_default_when_canvas_focused`, and the page calls `preventDefault` for it only while the canvas has focus. Alternative: a `web_alt` such as `alt+Right`, rejected because Alt+→ is Forward on Windows and Linux. shortcuts.json `web_reserved.prevent_default_when_canvas_focused`, spec §9.6.
- **D-18 Trackpads: two-finger scroll pans where the platform says it's a trackpad; in the browser it zooms.** Spec §6.2's trackpad column has two-finger drag pan and pinch zoom. Native macOS (and Wayland) report trackpad scrolling as pixel deltas and mouse wheels as lines, so a pixel-unit scroll pans (with the pivot under the cursor when the scroll starts) and Ctrl+scroll zooms to the cursor; `PinchGesture` zooms to the cursor and `PanGesture` (iOS) pans. Windows and X11 report precision touchpads as fractional line deltas, and browsers report both devices as pixel deltas (Chrome) or lines (Firefox), so there a two-finger scroll zooms like a wheel. Alternative: guess from delta sizes (multiples of 100 or 120, non-zero x), rejected as unreliable across browsers, drivers and smooth-scrolling mice. `gz-bevy::view::controls`.
- **D-19 Orthographic views drop TAA and SSAO for 4× MSAA, and measure fog and shadows from the scene's depth.** Bevy 0.20's screen-space effects assume a perspective camera, and an orthographic camera stands well back from its scene (D-20). Checked in the Bevy 0.20 sources: TAA's jitter is added to the projection's z column (`TemporalJitter::jitter_projection`), which for an orthographic matrix shifts each point by its view depth over the view width in pixels rather than a sub-pixel; SSAO's sample radius is divided by view depth and its view vector assumes an eye at the origin; shadow cascades are view-depth slabs from 0.1 to 150 m, where an orthographic camera has nothing; `DistanceFog` measures from the camera position, so it would add the standoff to every distance; the atmosphere traces sky rays from the camera to the near plane, which with orthographic near = 0 are perpendicular to the view (a degenerate zero vector at the centre). So in orthographic: no TAA (and its jitter and mip bias), no SSAO, 4× MSAA and Gaussian shadow filtering; cascades span the world's depth slab; linear fog moves out by the extra distance from the matching perspective eye and exponential fog thins to match at the pivot; the near plane sits at the view's reach, so the sky's rays spread like the matching perspective view's. Switching back restores the effects with TAA's history reset (also after H from an orthographic view). Bloom, exposure and tone mapping don't depend on depth. Alternatives: keep TAA (blurs by up to many pixels and varies with zoom), or render orthographic views without a standoff (clips the scene). The cascades are per light, so with split views (M6) the first view decides. `gz-bevy::render::projection_effects`.
- **D-20 Orthographic views keep the world in front; fly keys work in the screen plane.** After every change an orthographic camera stands at least the world's extent (its ground planes and the grid included, measured from the pivot) plus the view's reach behind the pivot, with the near plane at the reach and the far plane just past the world; this replaces a fixed 50 m standoff that the world could exceed and that picks and zooms could undo. The W/S fly keys move along the view axis in perspective, which in orthographic changes nothing until it clips, so there W/S move up and down the screen, A/D left and right, and Q/E zoom in and out (E out, as rising does over a top view). Fly speed and the scale `5` picks come from the depth of what's at the view centre (as snaps pick their pivot), kept between 2 cm and a framing of the whole world, not from the last click; zooming out stops at four whole-world framings, and the perspective far plane grows to keep the world inside it. `.agent/DESIGN.md` "Views".
  - *Amended (ortho fix, PR #37):* the extent the camera backs off from is at most 10 km from the pivot (`MAX_ORTHO_EXTENT`). A model that falls without a floor under it (the Jetty `diff_drive` world's `spawned_box`, at z ≈ −6 × 10⁹ m after a few hours) made the extent billions of metres, so the camera stood there, where `f32` steps are hundreds of metres, and nothing near the pivot could be placed: every orthographic view was blank. 10 km out, `f32` steps are about a millimetre, and a world of a few kilometres (outdoor, heightmap) stays whole, as it does in perspective, whose far plane grows to the world's far side. What lies more than 10 km from the pivot along the view axis is clipped in orthographic only. A first version capped at the perspective far floor (1000 m), which clipped kilometre-scale worlds that perspective shows (review). Alternatives: a negative near plane with the camera at the pivot (D-19's atmosphere and fog want the camera behind the near plane). The cap alone leaves focus, the zoom-out limit and the shadow cascades measuring the runaway model; the view's bounds leave such models out (follow-up).
  - *Amended (runaway models, PR #38):* the view's world bounds (what F frames with nothing selected or over a model, the zoom-out limit, the world's extent for the clip ranges and the shadow cascades) leave out every mesh that lies wholly more than 10 km (`RUNAWAY_DISTANCE`, the same as `MAX_ORTHO_EXTENT`) from the world origin. With the falling box, F framed a 6 × 10⁹ m world (the robot under a pixel, and an orthographic view blank again, since its reach was billions of metres), zooming out was all but unlimited, and the orthographic cascades spanned the 20 km slab #37's cap leaves (from the reach to twice the cap past it), about a hundred times coarser than for the world without the box. The filter is per mesh, not per model, so a link that fell off a model that is otherwise in place (a detached or jointless link, a nested model) is left out too; a first version judged whole top-level models and kept those (review). A selected runaway mesh is still framed: only the world's bounds leave it out. The threshold is the distance from the origin, not from the other meshes, so a world placed kilometres from its origin keeps its meshes; a world wider than 10 km leaves out what lies wholly past it, and a world that has all run away (or lies wholly 10 km from its origin) has only the grid: F goes home and zooming out stops at a few framings of it. Alternatives: an outlier test against the other models (no fixed scale, but a lone model far from a small world is a normal scene), or leaving the bounds alone (the symptoms above).

## 2026-10-19 · M1: theme, icons, fonts and widgets (`gz-ui`)

- **D-21 `theme.rs`'s tables are generated from `tokens.json` by `crates/gz-ui/build.rs`.** Every colour (light and dark), size, spacing step, radius, border width, duration, elevation and type style becomes Rust (`Palette`, `ColorRole`, `Sizes`, `SPACE`, `radius`, `border`, `motion`, `elevation`, `TypeStyle::*`); `src/theme.rs` holds only the hand-written parts (`Theme`, role components, systems). Alternative: the spec's hand-written mirror plus a test that it matches. Chosen so a token edit can't drift and needs no Rust change; a test still compares the generated tables with `tokens.json`. `ColorRole` covers every colour token (the spec's mirror listed a subset) plus `Clear` for transparent. Spec §4, `theme.rs` header.
- **D-22 State visuals come from `Hovered` and `Pressed`.** Bevy 0.20 removed `Interaction`; its headless widgets keep `Pressed` and `InteractionDisabled` and picking keeps `Hovered`. `button_visuals_system` reads those plus `Active`, `Checked` and `InteractionDisabled`. Spec §4.3.
- **D-23 UI scale is Bevy's `UiScale`, set from `Theme.scale`.** Builders use the logical sizes from `Theme.s` directly instead of multiplying by the scale. Alternative: scale every size at build time (§`theme.rs` note), which needs a rebuild of every node on change. Pointer movement arrives in window pixels, so anything that turns a drag into a size divides by `UiScale` (the splitter does; see D-41). Spec §10.
- **D-24 Filled icons are filled without a stroke.** icons.json: "stroke = currentColor, fill = none, stroke-width 1.75, round caps and joins, unless 'fill' is true". With a stroke as well, the pause bars would be 5.75 wide instead of 4. Atlas cells have a 2 px gutter; every texel is white, transparent ones included (D-44). The atlases hold the four listed sizes and every other size the spec draws icons at (D-44).
- **D-25 Geist Mono 600 uses Medium.** `tokens.json` lists Geist Mono Regular and Medium only, but `micro` (badges) and the number-field tag ask for 600. Keeping to the listed files (payload), weight-600 mono text uses Medium. Alternative: add GeistMono-SemiBold (+150 KB).
- **D-26 Geist has no ▾ ▸ ⌘ ⌥ glyphs: tree carets are chevron icons and shortcuts are spelled.** Shift-only chords print as `⇧F` (Geist has ⇧); others as `Ctrl+Shift+E`, `Cmd+…` and `Opt+…` on macOS, `Ctrl+…` in the browser. Key caps: Esc, Space, ⏎, ⌫, arrows (Geist Mono has them), so shortcut text is always set in Geist Mono, a tooltip's second line included (D-46). Alternative: a symbol fallback font (more payload). Spec §5.7, §5.14, shortcuts.json.
- **D-27 Text input is Bevy 0.20's headless `TextInput`, behind our NumberField.** It has selection, word and line movement, clipboard (async on wasm), IME composition, select-all on focus and scrolling. Gaps: no undo/redo, no AccessKit value or text selection, no placeholder, and Bevy text has no ellipsis (long labels clip). The NumberField wrapper owns parsing, commit and revert, so a replacement only changes its internals. Spec §9.5.
- **D-28 The gallery shows one theme at a time and is a gzweb option.** `--ui gallery` / `?ui=gallery` (not a `UiMode`: it runs no world, connection or viewer) with `--theme`/`?theme=`; T switches theme. Board 06 puts both themes side by side; doing that needs per-subtree themes, which nothing else needs, so the gallery is captured once per theme instead. Spec §12 item 1.
- **D-29 While a UI text field has focus, the viewer's keys are off and the canvas keeps every browser shortcut.** `gz_ui::focus` empties the viewer's `ActiveScopes` (spec §13: single-letter keys do nothing while typing; this also stops Space play/pause and the fly keys) and restores them on blur; global modifier chords wait too, until M2 routes keys by focus. In the browser the canvas listener skips `preventDefault` meanwhile, as for fields elsewhere on the page (§9.6: only while the viewport has focus), except for Tab (D-42). The scopes come back a frame after the field loses focus (D-43).

## 2026-10-19 · M2: the shell

- **D-30 Collapse and floor rules, as built.** The start-up rules (inspector collapsed below 1280 px, sidebar too below 1100) apply once, at start (to the window's first real size: D-53); afterwards only the floor rule acts. The floor rule collapses the inspector, then the sidebar, never the side the user just opened or widened (opening the inspector where both don't fit closes the sidebar), and panels it closed reopen, sidebar first, when the window grows enough; a user's own collapse is never undone. Splitter drags stop short of the floor instead of collapsing anything. Widths are in UI logical pixels (`UiScale` applied), so a larger UI scale reaches the narrow rules sooner. The status bar's "then 3 and 4" (§3.6) is a second threshold at 1100 px (alternative: measure the content, which bevy_ui can't report before layout). Spec §2.1, §3.6; `gz_ui::shell::layout`.
- **D-31 The 3D view renders into a texture that the view node shows, not into a `Camera::viewport` of the window** (amends §9.3). Checked in Bevy 0.20: the TAA pass (`bevy_anti_alias::taa`) samples the whole window-sized main texture with full-screen UVs and only restricts its output to the viewport, so the scene came out squeezed into the middle of the view at High and Ultra (Low, without TAA, was right); SSAO sizes its textures by the viewport while the prepass is target-sized. Rendering the main camera into an image of the view node's physical size keeps every effect correct, costs one UI quad, and renders no hidden pixels. `gz_bevy::view::ViewPlacement` carries the node's window rect (logical) and scale; `apply_view_placement` (PostUpdate, after UI layout and before culling) creates or resizes the image (no CPU copy, no copy-on-resize), points the camera at it and updates its target size and projection in the same frame, so a resize or splitter drag shows no frame at the old size. Pointer maths use the image's place in the window (`ViewOrigin`). Minimal mode is unchanged (the camera renders to the window). Alternatives: keep the viewport and drop TAA and SSAO in the full UI (worse quality); render the whole window with an off-centre projection (twice the pixels).
- **D-32 Pointer and key routing.** The camera gets presses, the wheel and gestures only when the pointer is inside the view node and bevy_picking's hover map has no UI node under it; the shell's pass-through containers (root, body, viewport area, view node, dimming) are `Pickable::IGNORE`, so any real panel, control, banner or card blocks the camera. A drag that started in the view continues over the UI. Viewport-scope keys (and the minimal fly keys) apply while the pointer is over the view, or after the last press was in the view (true at start); a press elsewhere, or a widget taking keyboard focus, hands them to the UI. Global chords (⌘B, ⌘⌥I, Space, ⌘→, panel shortcuts) work anywhere except while typing (D-29). The full UI's tool keys (Esc, B, T, R) change the tool's selection now; the tools act in M5. Spec §3.4, §9.3; `gz_bevy::view::controls::ViewRouting`.
- **D-33 One connect card on desktop and web.** The card reads "Connect to a Gazebo server" with the address field (the M1 text input), Connect and a status line (connecting, the last error and the retry count, loading the world), on both targets: the desktop card's Open world… / New world / Recent need the World menu's file features (M8), so it offers the "Connect to a running server…" part only (the Scene panel shows Open world… and New world disabled). The address is prefilled from the current server: in the browser `?url=`, else the last address the page connected to (`localStorage` `gzweb.last_url`, written on each successful connect), else this host. The card fades out over 160 ms once a world loads; while lost it comes back on "Connect to another server…". A connect to a new address starts over (card, not banner). `GzReconnect { url }` in `gz-bevy::connection` reconnects at once (cancelling the backoff and forgetting a rejected key or URL); Retry now and Reconnect send it without a URL. Spec §7.10.
- **D-34 The last frame dims toward `bg`.** "Dimmed to 70%" is a `bg` overlay at 30% over the view, which reads as dimmed in both themes (black at 30% would darken the light theme's frame but disappear in the dark one). The overlay passes the pointer through, so the camera still moves while disconnected; the transport and Reset are disabled without a live world. Spec §7.10.
- **D-35 The theme command is the Settings button for now.** `UiCommand::SetTheme` / `ToggleTheme` exist; until the Settings dialog (open) and ⌘K (M8, which lists "Theme: light / dark / follow system", §9.6) the activity bar's Settings button switches light ↔ dark. `--theme` and `?theme=` pick the start-up theme. No new shortcut: `ui.theme_*` are palette-only in shortcuts.json.
- **D-36 Panel header slot buttons.** With two slots both headers show one `move_to` button, "Swap slots": a panel can be in one slot only, so moving it to the other slot is a swap (and icons.json has no separate swap glyph; §13 forbids reusing one). With one slot it is hidden: moving the only panel would leave the primary empty. Pop out waits for pop-out windows (M7) rather than showing a dead button. The primary header keeps board 01's collapse chevron (⌘B); the secondary has close. Spec §3.3.2.
- **D-37 Shell readouts from what the server sends.** The websocket server reports no physics engine, so the status bar reads "— · 1 ms" (the step from `WorldStatistics.step_size`, kept while paused: D-56). Step is disabled while the sim runs (as in the Gazebo GUI and M0's ⌘→); Reset sends `GzCommand::Reset` directly (it isn't undoable: D-89). The Scene panel's loading skeleton shows while connected and waiting for the first scene; before that (connecting, or failed) it reads "No world loaded". Spec §3.1, §3.3.1, §3.6.
- **D-38 Captures of the full UI.** `--screenshot` keeps a UI mode named with `--ui` (`--ui full --screenshot` captures the workbench at 1440×900); `--window WxH` sizes the window or capture; `--capture-at-ms MS` shoots at that time instead of once the scene settles, for the connect card and the banner. The full UI's window starts at 1440×900 with a 1024×640 minimum (§2.1).

## 2026-10-19 · M1 review fixes

- **D-39 A NumberField commits only text the user edited.** The field remembers the text it last showed (`ShownText`); Enter or blur on text that still equals it commits nothing and shows the current value again. Before, blur re-parsed the rounded text ("2.457" for 2.4567) and committed it, so tabbing through pose fields truncated every value and sent it to the sim, and a value streamed in while the field had focus was overwritten by the stale frozen text. Alternative: a dirty flag set by text-change events (Bevy 0.20's `TextInput` has none to observe); comparing with `format(value)` (wrong once the value streams on). Typing the shown text back counts as no edit, which is harmless. Spec §13 "Focusing a live inspector field freezes it; blur without change resumes streaming."
- **D-40 In expressions a unit applies to the whole product or quotient before it, once.** `pi/2 rad` is (π/2) rad = 90°, the module's own example, which used to parse as π/(2 rad); `45deg*2` is 90°; `+`/`-` end the term (`3m + 20cm`). A second unit in one term (`90deg*2rad`) is an error rather than a guess. Parentheses nest at most 64 deep (`ExprError::TooDeep`) and unary signs are a loop, so no input can overflow the stack (5 000 `(` aborted a 1 MB stack before; wasm's is 1 MB). Alternative: units bind to the nearest number only (rejects the documented form). Spec §5.8.
- **D-41 Cursors: Bevy's `CursorIconPlugin`, and a drag holds its cursor.** `EntityCursor` does nothing without `CursorIconPlugin`, which only `FeathersPlugins` adds; `GzUiPlugin` adds it if missing. A mouse drag sets `OverrideCursor` to the cursor of what it started on (its own or nearest ancestor's `EntityCursor`, else the default) until it ends, so a splitter keeps col-resize while the pointer outruns its 6 px hit area, a scrub keeps ew-resize, and a slider drag keeps the arrow over a text field. Splitter drags divide by `UiScale` (D-23); splitters are tab stops with arrow keys (8 px), Home and End (the pane's min and max), as WAI-ARIA's window splitter, and the caller names them. Spec §5.18, §10.
- **D-42 Tab stays in the canvas while a UI text field has focus.** D-29 lets the browser keep every key's default while typing; Tab is the exception (with or without Shift, not with Ctrl/Alt/Cmd): Bevy's tab navigation moves UI focus, and the browser would also move DOM focus off the canvas, taking the keyboard away from the app. `InputMap::web_cancels`. The web gallery installs the same canvas listener. Spec §9.6, §6.5.
- **D-43 The viewer's keys come back one frame after a text field loses focus.** The key that blurred it (Esc, Tab) is still `just_pressed` in that frame, and the viewer's key handling runs later in the same frame, so a viewport Esc binding would also fire. Moving from field to field keeps the keys with the fields; scopes something else set while a field had focus are kept rather than overwritten by the saved ones. Alternative: clear `just_pressed` for the field's keys (reaches into Bevy's input state). Spec §13 Esc precedence.
- **D-44 The icon atlases have a cell for every size the spec draws, and white in every texel.** Sizes 10, 12, 13, 14 and 24 px join the listed 15, 17, 18 and 20 (tree carets, status-bar glyphs, the warning chip icon, play/pause and the eye, empty states), so none is downscaled from a 15 px cell without mipmaps; the 2× atlas grows to 832×1932. `build.rs` writes the PNGs itself with straight alpha and RGB 255 everywhere: tiny-skia's writer left transparent texels black, and linear filtering at UI scale 1.25 or 1.5 blended glyph edges toward black. Amends D-24 and the icons.json `$note` size list.
- **D-45 Widget systems work from change detection.** The state-visual, theme, toggle, menu-checkbox, tree-row, number-field focus, splitter-line, icon and tooltip systems visit only entities whose state changed (Changed/Added filters, `RemovedComponents`, focus moves for `HoverOnFocus`, added `Content`) instead of every widget every frame; the theme pass still resolves everything when the `Theme` changes. This is the base the §12 target of 5 000 tree rows needs. A disabled widget that is on keeps its active look with content at 40%: state isn't hidden by disabling (§10).

A drag moves the entities at once, sends their poses at most every 0.1 s (`SEND_SECS`) and on release (a release that moved nothing sends nothing, so a moving model isn't snapped back to where the press found it); meanwhile, until the server has answered every `set_pose` sent for them (in order, since a reply doesn't name its entity; given up on after 3 s, `REPLY_TIMEOUT_SECS`), and for 0.5 s after both the release and the answer (`HOLD_AFTER_EDIT_SECS`), the poses streaming from the sim for them are ignored (`Held`), so a slow server's stale poses don't pull them back either, so the stream doesn't pull them back under the pointer or flash the old pose before the edit lands. Alternative: apply nothing locally and wait for the sim (laggy over a network).
- **D-86 The editing tools are off unless the server takes edits.** Translate and Rotate (and T and R) are disabled with "This server can't take edits: it needs the websocket server fix (gz-sim pull request 4093)" until `GzStatus::edits` is yes; a server that answers no puts the tool back to Navigate, while a reconnect that is still asking leaves it (its button off until the answer). The UI's `Tool` sets `TransformTool` for the views.
- **D-87 The inspector's pose edits a movable subject.** With a server that takes edits, a movable model's (D-84) Pose group is a Position row and a Rotation row of three number fields (§5.8 tags, millimetres and tenths of a degree, as the text was); a link's and a light's stay text (a link's pose is its model's business; `set_pose` doesn't move lights, whose `light_config` service can wait). The fields stream like the text did and freeze on focus (D-39); a commit moves the subject at once and sends `set_pose` with the one value changed (rotation through Gazebo's fixed-axis roll, pitch, yaw), a scrub at most ten times a second (a step held back goes out once the time is up, so a scrub that stops on it doesn't spring back; its release commits the scrub's own value; a scrub that never changed the value commits nothing), and holds the stream for a moment after each step, as the gizmo does after a drag. The six numbers the fields set stand while the subject is still where they put it, so a scrub of pitch past ±90° carries on instead of turning into the same rotation's other angles at each step. The subject must still be movable when a commit lands: a plane found after the body was built turns the pose back to text. The fields read the subject's own transform, not the propagated one a frame behind. The body rebuilds when the server's answer changes. Multi-selection's shared pose stays read-only.
- **D-88 The joint command slider waits for a publish path.** JointPositionController takes commands on a topic, and the websocket server has no client publish (DESIGN.md "Server limits"), so the slider D-80 planned for M5c needs another server change; it is left out.
- **D-89 Undo is the client's, by scene path; Reset isn't undoable (amends §7.1, D-37, D-74).** `gz_bevy::undo::UndoStack` keeps each edit that dirties the world: a gizmo drag (one edit, from the press; Esc or a release that moved nothing records none), an inspector pose commit (a scrub is one edit from where it began: only its own field's steps join it, and anything else closes it, so a scrub cut short can't take in the next move), an eye, the inspector's Hide or Show, Hide others, and Isolate on or off (the saved visibility comes back with it, `gz_bevy::undo::Isolated`, now by path). Edits keep scene paths, so a respawn doesn't lose them; one whose entity is gone skips it. ⌘Z and ⇧⌘Z (global scope, so not while typing, and not during a gizmo drag or a field's scrub; `UndoSystems` runs after the gizmo and the keys) undo and redo; a move goes back as a `set_pose` (the sim's older poses held a moment, D-85), so on a running sim physics continues from the pose put back, and it waits while the server doesn't take edits; a hide needs no server. Each edit has a label for the World menu ("move cart", "hide 3 entities", "isolate"; M8 shows "Undo move cart"). The world is dirty while the stack isn't where it was at load, which the world button's unsaved dot shows. A new server or world clears the stack (it is the world's); a reconnect to the same world keeps its moves (the sim still has them) and forgets its hides and Isolate (the new scene comes with everything shown). Reset world is not undoable: the websocket server can't put a world's state back (velocities, joint states and sim time reset with the poses), so its "Reset world · Undo" chip would promise what the client can't do; a Reset (the client's, or the sim's iterations going back: another client's, or a restarted server) forgets the moves on the stack (gz-sim put them back) and keeps the hides, and with only hides left, undoing them is the world as loaded again. The world button's tooltip suffix ("· unsaved changes · ⌘S") waits for Save (M8). Delete's chip waits for Delete (M8). `gz_bevy::undo`; the shell's `shortcut_keys`.
- **D-90 Each view is a camera with an id, placed by its node; new views copy the first (§3.4, §9.3).** A view camera carries `gz_bevy::view::ViewId` (0 to 3) and its own `ViewPlacement` (a component now, not a resource), outline mask and render layer (`ViewId::layer`, 20 + id, besides the scene's 0). The full UI's view nodes name their view by id, since a new environment respawns every camera (`render::apply_environment` keeps each one's id, placement and state); `ViewSlots` says how many views the layout shows and `render::spawn_views` gives each a camera, dressed for the environment (fog, sky, light; a cubemap sky installs on every camera), as a copy of the first view's pose. A view the layout drops keeps its camera, off (`Camera::is_active`, a placement with no rect), so a preset brought back shows it as it was. Each view has its own rail, cube (its own cube scene on layer 30 + id), pills, outline and marquee, all children of its node, which find their camera from it (`ViewCameras::of`). Alternative: one camera moved between views (loses each view's state), or a fixed set of CAD views for new ones (Top, Front, Right): copying the view the user has set up is the less surprising start.
- **D-91 The pointer drives the view under it; keys go to the hovered, else the active, view (§3.4).** `ViewRouting` gained `hovered` (the view node the pointer is in, its controls included) and `active` (the view that got the last press, its rail or cube included; view 0 at start). A press, the wheel and gestures go to the hovered view, and a drag keeps the view it started in across the others. Viewport keys (F, H, 5, 7/1/3, G, the fly keys) go to the hovered view, else the active one. The transform gizmo shows, and picks, in the active view only (its config's render layer is that view's), and a gizmo drag keeps its view. The active view has a 2 px `accent` inset frame while several views show. The status bar's cursor readout reads the hovered view.
- **D-92 The layout is a grid of flex rows and columns with share dividers; Maximize, Close view and the floor (§2.1, §3.4, §7.4).** The five presets lay their views out with flex growth by each divider's share (column and row, kept per preset; Two columns 3:2, the rest even) and the 2 px gaps between, so views move in the frame the area does. A divider's 6 px hit area drags its share (each side at least `viewport_min` where it fits, an even split where it can't), a double-click resets it, and its gap is `accent` while dragging. The Layout popover picks a preset; Maximize (⇧Space) shows the key view alone and again restores, and Close view (⌘W) drops the key view for the preset with one fewer (Quad, One plus two, Two columns, Single), the views after it taking its place (their cameras take the ids down). ⌥⌘→ and ⌥⌘↓ split towards Two columns, Two rows, One plus two and Quad. The floor rule asks the area for every view at `viewport_min`: wider layouts collapse the inspector, then the sidebar, and a layout that still doesn't fit (or is too short) shows Single until it does. `gzweb --layout PRESET` starts in a layout for captures. Link cameras, Shared selection, per-view overlays and the inactive views' face marker are M6b.
